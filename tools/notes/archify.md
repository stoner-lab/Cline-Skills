## Cline runtime notes (read first)

- **Skill directory:** the folder that holds this `SKILL.md`, written `<skill>` everywhere below and in `references/`. Installed: `C:\Users\<user>\.cline\skills\archify\`; in the source repo: `E:\Private\Projects\Cline-Skills\archify\`. Replace `bin/archify.mjs` in every command with `<skill>\bin\archify.mjs` (absolute path), and run the command from the working directory the artifact belongs to.
- **Tools:** `Read` -> `read_files`; `Write`/`Edit` -> `editor`; shell -> `run_commands` (PowerShell); search -> `search_codebase`. Bash examples in `references/` map to PowerShell: use `;` instead of `&&`, `node <skill>\bin\archify.mjs ...` directly, and quote paths that contain spaces.
- **Requirements:** Node 18 or newer (this machine has v24). Everything is dependency-free: `bin/`, `renderers/`, `schemas/`, `references/` and `examples/*.json` ship inside the skill. Never run `npm install`, `npm i -g` or any package manager for this skill, and never install Node/Chrome without asking.
- **Check the machine before the first diagram:** `node <skill>\bin\archify.mjs doctor`. It prints 27 checks and `Archify is ready.` on success. A quick end-to-end proof: `node <skill>\bin\archify.mjs demo <temp-dir>` and confirm `<temp-dir>\archify-demo.html` was written.
- **Artifacts:** one folder per request, `.archify\<type>-<slug>-<YYYYMMDD-HHMMSS>\` in the working directory, holding `candidate.json` (or `candidate.archify.md`) and the rendered `<slug>.html`. Repairs reuse the same folder; a new request gets a new folder. Do not write inside the skill folder.
- **`examples/` here holds the `.json` sources only** (the rendered `.html` files were dropped to keep the repo small). Treat `examples/*.json` as the reference shape for each diagram type; `doctor` still passes with them.
- **Browser steps:** `preview` and `visual-check` open a local Chromium/Chrome headlessly. If they cannot find a browser or the session forbids browser automation, skip them, rely on `render` plus `finalize` receipts, and say plainly in the reply "automated checks passed; not visually reviewed". The Playwright tools are never a substitute for the skill's own checkers.
- **No subagents:** the run is inline, one command at a time, even where the upstream text says to fan out. Do not edit `renderers/`, `schemas/`, `bin/` or `references/` to silence a validation finding; report the finding instead.
- **Language:** answer the user in Vietnamese (or their language). Diagram labels and titles follow the language of the subject or the brief.
- **Reply shape:** one clickable Markdown link to the produced HTML with an absolute path (wrap it in `<...>` when the path has spaces), one or two sentences of takeaway only when the user wants to understand a system, and one line for anything that changes how the diagram must be read (abstract level, illustrative values, missing evidence). No command recaps, hashes or check lists. On request, open the file with `Start-Process <path>`.
