## Cline runtime notes (read first)

- **Skill directory:** the folder that holds this `SKILL.md`, written `<skill>` everywhere below and in `references/`. Installed: `C:\Users\<user>\.cline\skills\design-taste-frontend\`; in the source repo: `E:\Private\Projects\Cline-Skills\design-taste-frontend\`. Paste the absolute path wherever a command says `<skill>`; the rest of the folder is upstream and runs as written.
- **Tools:** `Read` -> `read_files`; `Write`/`Edit` -> `editor`; shell -> `run_commands` (PowerShell); search -> `search_codebase`; a quick visual look -> the Playwright MCP tools. Every step of this skill is a plain `node <skill>\scripts\<name>.mjs …` call, so no bash is needed: use `;` instead of `&&`, and quote paths that contain spaces.
- **Requirements:** Node 22+ and Chrome, Edge or Chromium (headless; the checkers find it themselves, `CHROME_PATH` overrides). ffmpeg is optional - it only adds WebP files and the 780x584 phone crop. No npm packages: every script is dependency-free.
- **Check the machine before the first page:** `node <skill>\scripts\check_env.mjs`. It prints Node, the browser, the kit files and `library/*.json` with a fix list and exits 1 when something required is missing. On FAIL the run stops there: give the user the list and **ask before installing anything** (Node, Chrome, ffmpeg, packages). No silent `winget`, `choco` or `npm i -g`.
- **Build in the user's project folder, never inside the skill folder:** `<project>\index.html`, `<project>\assets\` (a copy of `<skill>\assets`), `<project>\.taste-skill\` (deal history), `<project>\shots\` (screenshots). Pass `--profile <project>\.taste-skill\chrome` so the checker's browser profile stays out of the way.
- **One script at a time.** Each check opens its own headless Chrome over `127.0.0.1` and stops it by PID; two at once collide on the profile and the port. `consistency.mjs` at five widths takes tens of seconds; say so before a run that takes minutes.
- **The skill's own checkers are the check.** The Playwright MCP tools are for a quick look the user asked for, never a replacement for `consistency.mjs`, `assets\layout\check.mjs`, `shoot.mjs` or `perf.mjs`, and kit files (`assets\`, `scripts\`, `library\`, `references\`) are never edited to clear a finding - report the finding instead.
- **Ask for the real material** before building when the brief is thin (SKILL.md section 4, step 1): what is sold, who buys it, the one main action, the real logo, screens, photographs, address and hours. One question, then build; a client's facts are never invented.
- **No subagents:** the run is inline, one step at a time, even where the upstream text says to work in parallel.
- **Encoding:** all files are UTF-8 and the pages load Google Fonts over the network; a build without network access falls back to the system stack and the `font-load` check will WARN.
- **Language:** answer the user in Vietnamese (or their language); the page copy, class names and commit text stay in the language the brief is in, usually English.
- **Report in chat, not in a file:** the kind, the deal (palette, pairing, hero, grounds, effect, moments), the check results, what could not be checked, every assumed price, hour or address, and every frame the client must supply.
